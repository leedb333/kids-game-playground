# 요리놀이 2.0 — 피자 4단계

## 실행과 보존 범위

- 새로운 요리 선택/정식 피자 경로: `/kids-game-playground/prototypes/cooking-v2/kitchen/`.
- 진행 중 피자 직접 진입: 위 주소 뒤에 `#pizza`.
- 기존 검증 시험판 `/kids-game-playground/prototypes/cooking-v2/`는 계속 사용할 수 있다.
- 기존 통합 홈은 여전히 기존 요리놀이를 실행한다. 색칠놀이·기존 요리놀이·코디놀이·벽돌깨기·짝꿍 카드 소스는 변경하지 않았다.
- 최신 main `b5cfa258`에서 시작했다. 시험판 PR #21은 병합된 상태이며 원본 브랜치의 검증 기능을 재사용한다.
- 작업 브랜치: `feat/cooking-v2-pizza-full`. 자동 병합·배포하지 않는다.

## 추가 기능과 재사용 구조

1. 반죽 덩어리 → 중간 반죽 → 기존 평평한 도우의 3상태를 밀대 움직임과 연결했다.
2. 검증된 소스 마스크·면적 계산·기존 재료 이미지·배치 좌표·입력 취소·이동/제거/되돌리기를 `Workbench.tsx`로 추출했다. 기존 시험판과 새 피자가 같은 기능을 사용한다.
3. 새 피자의 토핑은 치즈·페퍼로니·버섯·양파·파프리카·올리브 6종이다. 기존 시험판은 기존 3종을 유지한다.
4. 피자 트레이 드래그, 오븐 문 열기/닫기, 약 4초 굽기, 조명·반짝임, 완료 소리, 큰 접시와 PNG 저장을 추가했다.
5. 새 요리 선택 화면은 피자만 활성화하고 나머지 세 요리는 준비 중으로 표시한다.
6. 공통 저장 훅 `useSavedRecipe<T>`는 요리별 저장 키·상태·검증 함수를 받는다. 요리 목록은 별도 데이터이며, 다른 요리가 피자 반죽/오븐 규칙을 억지로 사용하지 않도록 피자 세션 로직은 `full/session.ts`에 분리했다.

## 이미지 자료와 품질 검수

공식 시안은 소스(1920×1080), 토핑(1024×473), 오븐(2208×1242)을 참고한다. 시안은 확장자는 PNG지만 실제 내용은 JPEG이다. 화면 전체를 클릭 이미지로 사용하지 않는다.

기존 검증용 8종과 기존 가공본 12종은 보존한다. 기존 소스·페퍼로니·버섯·생치즈·배경·도우·도마·숟가락의 RGB 질감은 변경하지 않았다. 원본 해시 검증은 시험판 테스트에서 계속 수행한다.

부족했던 음식 에셋 7종은 이미지 생성 기능으로 별도 제작하고 실제로 열어 확인했다. API/CLI나 외부 이미지 다운로드는 사용하지 않았다. 생성 원본은 `public/assets/cooking-v2/pizza/full/`, 사용 가공본은 `src/games/cooking-v2/assets/`에 보관한다. 프롬프트 원문은 [generation-prompts.json](generation-prompts.json), 실제 원본 크기·SHA-256·투명 픽셀·크롭 좌표는 [asset-audit.json](asset-audit.json)에 기록했다.

오븐, 밀대, 트레이, 접시는 음식 대용 그림이 아닌 개별 SVG/CSS 도구다. 오븐 몸체, 피자 트레이, 문 전경을 서로 다른 레이어로 관리한다. 반죽·토핑은 프로그램 도형으로 다시 그리지 않았다.

## 4단계 조작과 상태

### 반죽

- 밀대 버튼을 잡아 도우로 가져오거나, 선택된 밀대로 반죽을 직접 문지른다. 좌우·앞뒤 방향 모두 인정한다.
- 도우 근처의 유효 이동량 1600 기준 좌표 단위가 쌓이면 완료한다. 순간 점프 입력은 한 번에 최대 80만 인정한다. 정밀한 선 긋기나 정해진 순서는 요구하지 않는다.
- 이동량에 따라 크기가 부드럽게 늘고, 별도 제작한 덩어리/중간/기존 도우를 교차 표시한다. 기존 평평한 도우 한 장을 작게 축소한 것으로 덩어리를 대체하지 않았다.
- 손가락을 뗄 때 한 동작을 저장한다. 취소된 터치는 확정하지 않으며 되돌리기로 직전 움직임 전 상태를 복원한다. 키보드는 밀대 선택 후 반죽에서 Enter/Space로도 진행 가능하다.

### 소스

기존 Canvas `source-in` 마스크와 65% 면적 기준을 재사용한다. 도우 바깥은 칠하지 않는다. 단계 전환 후에도 아이가 칠한 경로 그대로 유지한다. 도우 밖으로 나갔다 돌아온 경로를 새로 시작하여 불필요한 직선을 방지한다.

### 토핑

터치 선택 후 피자를 누르거나 재료 카드를 끌어 놓는다. 위치·회전·크기·종류·그룹 ID를 저장한다. 치즈는 작은 가닥 묶음으로 뿌리고, 다른 재료는 한 조각씩 반복 배치한다. 같은 위치에 너무 몰리면 새 피자에서는 주변의 가까운 유효 위치를 찾아 약간 옮겨 놓는다. 아이가 고른 위치에서 크게 멀리 보내거나 실패로 처리하지 않는다.

배치 후 옮기기·빼기·동작 단위 되돌리기를 제공한다. ‘오븐에 넣기’는 아이가 직접 선택한다. 토핑 수 때문에 자동 진행하지 않으며, 토핑이 없어도 다음 단계로 갈 수 있다.

### 오븐과 동일 피자 보존

`closed → open → inside → baking → done` 상태를 사용한다. 문을 열고 트레이를 오븐 영역으로 드래그한 뒤 문을 닫는다. 키보드와 어린이 접근성을 위해 같은 동작의 하단 버튼도 제공한다.

조리 전후에 `work.actions`를 수정하지 않는다. 같은 `renderPizza`와 같은 토핑 배열을 사용하고, 굽기 비율에 따라 베이스를 구운 크러스트로, 각 치즈를 같은 위치의 녹은 치즈로 부드럽게 바꾼다. 피자 전체를 미리 그려 둔 완성 피자 이미지로 교체하지 않는다. 토핑 ID·종류·개수·위치·회전·저장 크기는 그대로다.

활성 화면에서 약 4초간 굽는다. 다른 화면으로 나가거나 초기화 확인창을 열면 진행을 멈추며, 저장된 경과 시간으로 재개한다. 앱이 보이지 않을 때도 굽기 진행을 멈춘다. 종료 시 짧은 소리를 내며 소리 끄기를 존중한다.

## 완료와 PNG

큰 접시 위에 같은 피자를 보여주고 김·별·축하 문구를 표시한다. ‘PNG 저장’은 1400×1400에 접시와 동일 피자 렌더러만 그린다. 버튼·메뉴·문구·캐릭터는 PNG에 포함하지 않는다. PNG 저장을 누른 순간의 작품 상태를 사용하므로, 저장 중 요리 선택으로 나가도 새 반죽으로 바뀌지 않는다. 실제 다운로드 파일은 [finished-pizza.png](finished-pizza.png)에서 볼 수 있다.

완성 후 요리 선택으로 돌아가면 새 피자를 시작하도록 현재 정식 피자 세션만 초기화한다. 완료 화면에서 새로고침한 뒤 다시 선택해도 ‘만들기 시작’으로 동작한다. 진행 중에 요리 선택으로 나갔다 돌아오면 이어서 만든다.

## 저장과 초기화

- 새 전용 키: `kids-game-playground:v1:game:cooking-v2:pizza:full:r1`.
- 기존 시험판 키 `...:prototype:r1` 및 기존 다섯 게임의 키는 수정하거나 삭제하지 않는다.
- 반죽 진행, 소스 경로, 토핑, 현재 단계, 오븐 상태·경과 시간을 저장한다.
- 다시 만들기는 확인창 승인 후 현재 정식 피자만 초기화한다. 취소하면 현재 조리 상태를 유지한다.
- 저장이 차단되면 안내하고 플레이를 계속한다. 잘못된 세션 데이터는 새 피자로 복구한다. 에셋 로딩 실패 시 오류를 표시하며 도형 음식으로 대체하지 않는다.

## 자동 검증과 화면 검수는 별도

TypeScript 검사, Vite 프로덕션 빌드, GitHub Pages 경로 검사가 통과했다. 전체 221개 테스트가 통과했다(10.0분). PNG 저장 버튼을 누른 직후 요리 선택으로 이동해도 동일한 작품을 저장하도록 보완한 뒤, 정식 피자 11개 테스트를 다시 실행하여 통과했다(50.5초). 기존 큰 JavaScript 청크 경고는 유지되며 빌드 실패는 아니다. `tests/cooking-v2-full.spec.ts`는 11개 테스트로 실제 4단계 플레이, 실제 터치 입력을 모사한 이벤트 밀대/트레이 드래그, 소스·6종 토핑, 정확한 조리 전후 배열 비교, PNG 다운로드, 취소/되돌리기, 초기화 확인, 저장/재개, 오프라인, 5개 화면 크기를 검사한다. 기존 시험판 13개와 기존 다섯 게임 197개도 함께 실행한다.

## 시안 대비 차이와 남은 한계

- 파스텔 주방, 큰 음식, 실제 재료 질감은 검증된 시험판을 유지했다. 시안의 장갑·그릇·캐릭터는 새로 끼워 넣지 않았다.
- 시안의 빨간 대형 오븐 대신 현재 주방에 맞는 연한 코랄색 오븐을 개별 레이어로 구성했다. SVG 도구의 매끈한 표면과 음식의 사실적인 질감에는 그림체 차이가 있다.
- 반죽 변형은 별도 이미지 간 교차 표시와 크기 변화다. 실제 물리 반죽 시뮬레이션은 아니다.
- 치즈는 가닥별로 녹은 질감이 되며, 여러 가닥이 하나의 큰 유체 덩어리로 합쳐지는 시뮬레이션은 하지 않는다.
- 채소·페퍼로니·버섯은 아이가 고른 원본 모양을 유지한다. 각 채소가 따로 익거나 수분이 빠지는 변형은 없다.
- 올리브는 완전한 검정 대신 기존의 따뜻한 조명에 맞는 짙은 갈색이다. 치즈 원본 무더기에서 추출한 가닥의 가장자리 한계도 유지된다.
- 새 가공 이미지 용량은 약 6.8MB 증가했고 전체 음식·배경 가공본은 약 17.8MB다. 캐시 설치가 끝난 뒤 오프라인으로 사용할 수 있으며 최초 온라인 로딩이 필요하다. 원본/가공본은 모두 저장소 안에 있다.
- 추가 필수 음식 에셋의 미확보로 막힌 단계는 없다. 더 정교한 손/그릇 연출과 유체 치즈는 추후 품질 확장 범위다.
