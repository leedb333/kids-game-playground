# 컵케이크 3개 동시 제작 — 1차 분석 및 구성 검증

**이 브랜치는 사전 검증입니다. 운영 게임은 변경하지 않았습니다.** 그림 재료 카드·3구 트레이·연속 굽기·3개용 실제 저장/이어하기는 아직 구현되지 않았습니다. 새 음식 이미지도 제작하지 않았습니다.

PR #25는 `2026-11-15` 병합된 상태를 확인했습니다. 최신 main `ac38e42`에서 `plan/cupcake-three-asset-validation` 브랜치를 만들었습니다. 기존 PR을 다시 열거나 병합·배포하지 않습니다.

공식 시안 3종과 원본 9종을 열어 확인했습니다. 원본은 배경 1672×941 RGB 1종, 나머지 1254×1254 RGBA 8종입니다. 원본 SHA-256이 기존 검수 기록과 모두 일치했습니다. [현재 에셋 검사](asset-audit.json)에 크기·알파·해시를 기록했습니다.

## 2. 재사용 가능한 것

- 분홍 주방, 거품기, 짤주머니, 두 크림, 스프링클 원본과 작은 가공본 3종.
- 분홍색 구운 기본 컵케이크: 같은 분홍 컵 3개를 표현할 수 있음.
- 선택한 컵 하나를 크게 그리는 기존 합성기와 크림 실제 알파 영역 제한.
- 크림 선택/진행, 장식 좌표·회전·크기, 제거와 되돌리기 함수.
- 확대된 오븐 SVG, 문 동작과 기존 트레이 이동 처리의 기본 방식.
- 기존 반투명 완성 말풍선, 공통 저장 훅, PNG 생성 방식.

기존 6구 트레이의 앞줄/뒷줄 컵과 프레임이 겹쳐 있어 한 줄을 잘라 3구 트레이라고 쓰지 않습니다. 완성 반죽이 들어 있는 볼에서 재료를 실제로 넣고 섞는 전체 변화도 현재 그림만으로는 자연스럽게 만들기 어렵습니다.

## 3. 필요한 이미지

**최소 신규 13장**을 제안합니다: 재료 카드 4장, 볼 안 재료 레이어 4장, 빈 볼 1장, 3구 트레이 1장, 같은 분홍 컵의 빈 상태/반죽/중간 굽기 3장. 완전 구움은 기존 기본 컵 재사용을 우선합니다.

파일명·해상도·투명 배경·정렬·제작 순서는 [ASSET-BRIEF.md](ASSET-BRIEF.md)에 정리했습니다. 컵 테두리가 상태마다 달라지면 분리형 앞면/내용물 이미지가 추가로 필요합니다. 최종 개수는 새 상태 세트의 정렬 검수 후 확정합니다.

## 4. 3구 트레이 설계

- 한 줄 3구 트레이 PNG 한 개와 컵 상태 PNG 3개를 별도 요소로 합성합니다.
- `cup-1`, `cup-2`, `cup-3` ID와 `traySlot`은 처음부터 PNG 저장까지 유지합니다. 번호는 그림에 넣지 않고 실제 버튼으로 표시합니다.
- 반죽 볼/도구를 고른 뒤 컵의 넓은 터치 영역에 터치/드롭합니다. 선택된 컵의 `fillProgress`만 증가합니다. 이미 채운 컵도 선택할 수 있습니다.
- 세 컵이 모두 채워진 후에만 트레이를 오븐으로 이동할 수 있습니다. 별도 ‘컵트레이’ 선택 버튼은 제거하고 트레이 자체를 드래그합니다.
- 트레이는 하나의 부모 좌표계로 이동·축소합니다. 컵은 고정된 로컬 앵커를 사용해 이동 전후 배열이 바뀌지 않게 합니다.

**실제 3구 그림과 컵 채움은 아직 미구현**입니다. 구성 검증 화면에 임시 트레이나 가짜 재료 그림을 넣지 않았습니다.

## 5. 3개 동시 굽기 설계

- 오븐 시간은 공통 약 3초, 각 컵은 독립 ID와 굽기 상태를 유지합니다.
- 정렬된 반죽→중간→완성 이미지의 내용물 영역만 같은 자리에서 전환합니다. 컵과 트레이는 고정합니다.
- 서로 다른 캔버스 여백의 이미지를 개별 중앙 정렬하지 않습니다. 상태 세트 전체에 공통 crop/앵커/배율을 적용합니다.
- 종이컵을 통째로 키우거나 별도 완성 컵을 다른 위치에 추가하는 기존 방식은 사용하지 않습니다.
- 종이컵 앞면을 공통 레이어로 고정하거나 검수된 내용물 마스크를 사용합니다. 중간 상태가 없는 채로 사실적인 부풀기를 완료했다고 보고하지 않습니다.
- 굽기가 끝나면 문을 열어 같은 세 컵을 보여준 후 꾸미기로 갑니다. 확대 오븐과 반투명 말풍선은 유지합니다.

## 6. 개별 꾸미기 데이터

권장 새 구조의 핵심은 다음과 같습니다. [예시 JSON](proposed-state-example.json)은 **제안용이며 운영 저장 파일이 아닙니다**.

```ts
type CupId = 'cup-1' | 'cup-2' | 'cup-3'
type Cup = {
  id: CupId
  traySlot: 0 | 1 | 2
  fillProgress: number
  bakeProgress: number
  design: {
    cream: 'vanilla' | 'strawberry'
    piping: number
    sprinkles: {id:number;kind:string;u:number;v:number;rotation:number;size:number}[]
    nextId: number
    done: boolean
  }
}
```

상위 작업에는 공통 재료/섞기 진행, 오븐 경과 시간, 선택 CupId, 컵 배열을 둡니다. 꾸미기 되돌리기는 CupId별 이력을 사용하여 선택하지 않은 컵이 바뀌지 않게 합니다. 단계 이전 이력과 각 컵 이력을 구분하고 저장 용량 상한을 둡니다.

상단 또는 한쪽의 미리보기 카드 3개와 중앙 큰 컵을 사용합니다. 맛만 선택해서 완료시키지 않습니다. 실제 크림 짜기 진행이 일정 수준(제안 40%) 이상일 때 ‘이 컵 완료’를 누를 수 있게 하고, 세 컵의 완료 상태를 명확히 표시합니다. 부담 없는 건너뛰기는 별도 명시 동작으로만 검토합니다. 이는 **2차 UX 제안**이며 현재 게임 조건을 바꾼 것이 아닙니다.

## 7. 저장 호환성

현재 키 `kids-game-playground:v1:game:cooking-v2:cupcake:prototype:r1`은 덮어쓰지 않는 방식을 권장합니다. 새 버전 키와 `version:2`를 사용하고 기존 JSON은 보관합니다. 이번 브랜치는 어떤 실제 저장 키도 변경하지 않습니다.

- 기존 반죽 단계는 재료/섞기 진행을 그대로 옮길 수 있습니다.
- 굽기 전 기록은 기존 채움 상태를 1번 컵으로 가져오고 나머지 두 컵을 비워 둘 수 있습니다.
- 기존 굽기 중·꾸미기·완성 기록은 ‘세 컵을 함께 구운 기록’으로 무손실 변환할 수 없습니다. 자동으로 세 컵의 굽기를 완료 처리하지 않습니다.
- 이 경우 먼저 안내/확인 화면에서 ‘기존 그림을 1번으로 가져와 꾸미기부터 시작(추가 두 컵은 구운 기본 컵으로 준비)’ 또는 ‘기존 기록을 보관하고 새 반죽부터 시작’을 명확히 선택하게 합니다. 취소하면 새 저장을 쓰지 않습니다.
- 가져오기 전/후 버전을 검증하고 저장 성공 후에만 새 버전을 사용합니다. 기존 raw JSON과 그림·장식 좌표를 백업합니다. 이력 형식 변경/초기화가 필요하면 미리 설명하고 확인합니다.
- 기존 피자·햄버거 및 다른 게임의 키는 읽거나 쓰지 않습니다.

실제 마이그레이션·확인창·게임 재접속 이어하기는 아직 구현/검증하지 않았습니다. 이번 검증의 JSON 왕복 검사는 직렬화 가능성만 확인합니다.

## 8. 실제 1차 검증

`scripts/validate-cupcake-three.mjs`는 운영 진입점 없이 임시 브라우저 검증 화면을 만듭니다. 기존 `model.ts`, `assets.ts`, `renderCupcake()`를 메모리 안에서 번들링해 그대로 사용합니다. 별도 파일로 게임 엔진을 복사하지 않습니다.

검증한 내용:

1. 원본 9종 형식·크기·투명도·해시.
2. 딸기/바닐라/딸기와 장식 3/6/9개의 독립 상태.
3. 3번→1번 선택 시 크림과 장식 유지.
4. 선택한 컵의 장식 추가/되돌리기와 다른 컵 불변.
5. 개별 장식 제거/복구.
6. 실제 디자인 3개와 기존 접시를 합성한 1400×1400 투명 PNG. 검증 화면 Canvas와 픽셀 차이 0.
7. 제안 데이터 JSON 직렬화 왕복.
8. 태블릿·폰 크기의 구성 검증 화면에서 가로 넘침 없음.

[결과 JSON](study-results.json), [저장 PNG](three-cupcakes.png).

**검증 버튼은 시험 도구입니다.** ‘크림 올리기 검증’은 한 번에 크림을 채워 렌더링을 확인하는 버튼이며 정식 게임의 길게 누르기/드래그를 대체한 구현이 아닙니다. 3개용 터치 통합과 실제 저장은 2차에서 연결해야 합니다.

## 9. 기존 게임 영향

운영 `src/`, `public/`, 홈, 요리 선택, Vite 설정, 의존성, 저장 키를 수정하지 않았습니다. 브랜치에는 분석 문서·검증 스크립트·캡처만 추가합니다. 기존 앱 타입/빌드와 컵케이크·피자·햄버거·홈 진입의 선택 회귀 테스트를 실행합니다. 수치는 최종 결과에 기록합니다.

2026-11-15 최종 검증: 독립 구성 검증 **8개 검사 그룹 통과**, TypeScript·Vite build·Pages 경로 검사 통과, 기존 컵케이크 22개 + 피자/햄버거 end-to-end 2개 + 홈의 기존 5게임 진입/복귀 1개 = **관련 회귀 테스트 25개 통과(2.2분)**. [실행 기록](regression.log).

운영 코드가 바뀌지 않은 사전 검증이라 전체 276개 테스트는 이번에 재실행하지 않았습니다. 3개 제작의 정식 기능도 통과했다고 보고하지 않습니다. [요청 21항목별 검증 상태](TEST-MATRIX.md)를 구분해 기록했습니다.

## 11. 2차 권장 순서

1. [제작 요청서](ASSET-BRIEF.md)의 A 5장을 먼저 확보하고 컵 상태 정렬 검수.
2. 나머지 B 8장 확보 및 볼 안 합성 검수.
3. 3컵 ID/채움/공통 굽기와 고정 앵커 구현.
4. 기존 크림·장식을 선택 CupId에 연결하고 CupId별 되돌리기/완료 처리.
5. 화면/PNG의 공통 3개 배치를 확정하고 내보내기 구현.
6. 기존 기록 보관과 사용자 확인을 포함한 저장 이전 구현.
7. 모든 단계의 실제 터치·저장·PNG·반응형 및 기존 게임 회귀 검증 후 정식 검토.

핵심 에셋이 확보되기 전에는 3개 동시 제작이 완성됐다고 보고하지 않습니다. 새 파일은 검수 전부터 자동 배포하지 않습니다.
