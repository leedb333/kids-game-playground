# 기존 원화 재활용 합성 시험 — 정식 게임 미반영

## 결론

기존 고품질 원화와 승인 카드 4종·트레이 1종만으로 **재료 질감의 짧은 투입 효과, 거품기 조작, 기존 완성 컵 3개 배치, 독립 상태, 트레이 그룹 이동**은 가능합니다. 그러나 **진짜 빈 믹싱볼 복원, 빈 컵의 뒤·안쪽 복원, 자연스러운 생반죽→구움 표현은 시각 검증 실패**입니다. 픽셀 검사와 자동 테스트 통과를 그림 품질 통과라고 부르지 않습니다.

새 원화 생성·운영 화면 변경·저장 데이터 변경은 하지 않았습니다. 불합격 이미지 8종은 로딩하지 않습니다. 시험 결과 PNG는 문서 증거로만 저장했으며 정식 에셋 폴더에 추가하지 않았습니다.

저장소 폴더에서 다음 명령을 실행합니다.

```powershell
node node_modules/vite/bin/vite.js --host 127.0.0.1 --port 4186 --strictPort
```

그다음 브라우저에서 아래 주소를 엽니다.

`http://127.0.0.1:4186/kids-game-playground/experiments/cupcake-reuse/`

A 재료·볼 / B 종이컵 / C 트레이 / D 이동·굽기 탭으로 시험합니다. 각 화면에 한계를 표시했습니다. **로컬 개발 서버 전용 경로**이며 운영 빌드의 진입점에 넣지 않았습니다. `dist/experiments`가 없음을 확인했습니다. 홈/요리 선택/서비스워커/배포 설정을 변경하지 않았으므로 GitHub Pages에서 이 시험 경로가 실행된다고 안내하지 않습니다.

## A — 재료 투입과 믹싱볼

- 승인 카드 4개에서 재료를 고릅니다. 카드 선택 후 볼을 터치하거나 '선택 재료 넣기'를 누르면 약 700ms 동안 작은 음식 질감만 이동하고 내부에서 사라집니다. 카드·문자·프레임 전체가 들어가지 않습니다.
- 카드 내부의 노른자/우유 튄 부분/밀가루/설탕 질감을 **Canvas에서만 잘라** 부드러운 알파 가장자리를 적용했습니다. 최초 잘라보기에서 우유팩 파랑과 그릇 테두리가 섞여 보이는 문제를 발견해 실제 음식 내부로 범위를 조정했습니다. 가공 PNG를 정식 신규 에셋으로 등록하지 않았습니다.
- 최종 카드 원본 1024² 기준 crop `[x,y,width,height]`: 달걀 `[450,595,150,100]`, 우유 `[440,640,90,60]`, 밀가루 `[395,235,120,80]`, 설탕 `[545,485,120,80]`. 모두 3:2 비율을 유지합니다. 재료 전체를 추출한 그림이 아니라 작은 투입 효과용 질감입니다. 큰 우유 붓기·달걀 깨기 애니메이션을 확보했다고 주장하지 않습니다.
- 볼 내부 타원 `(622,450), rx=470, ry=155`와 상단 이동 영역으로 클리핑해 앞 테두리·하트를 덮지 않게 합니다. 기존 `mixing-bowl-batter.png`는 그대로 그립니다.
- 중복 재료·동시 투입을 막고 네 재료를 모두 넣은 뒤 Pointer Events로 원을 그리면 섞기 진도가 올라갑니다. 키보드는 거품기를 선택한 뒤 좌우 화살표로 시험할 수 있습니다. 입력 취소 후 남은 이동이 적용되지 않는지도 검사했습니다.
- **한계:** 원본에는 처음부터 반죽이 있습니다. 비어 있거나 재료만 담긴 볼이 아닙니다. 네 재료를 넣은 뒤 보이는 반죽도 기존 표면이며 빈 볼에서 채워지는 조리 과정을 복원한 것은 아닙니다.

`A-before.png`, `A-pour.png`, `A-stirred.png`, `card-texture-*.png`에 결과를 남겼습니다.

## B — 종이컵 앞면 고정

기존 `cupcake-baked-base.png`에서 분홍 앞면의 색 경계를 찾고 연속 경계 마스크로 앞면/내용물을 분리했습니다. 이전 열별 잘라붙이기보다 매끈하게 해보되, 공유 마스크 안의 원본 RGBA 픽셀은 그대로 재사용했습니다. 종이컵 전체를 확대하지 않았습니다.

| 상태 | 시험 합성 | 시각 판단 |
|---|---|---|
| 빈 컵 | 기존 앞면만 표시 | 뒤·안쪽 원화가 없어 구멍과 불완전한 입구가 보임 — 실패 |
| 반죽 | 기존 반죽 표면을 안쪽에 배치 + 같은 앞면 | 이음새·물결 테두리 경계 미흡 — 실패 |
| 조금 부푼 | 케이크 내용물만 점진 확대 + 같은 앞면 | 표면 고리와 이음새가 보임 — 실패 |
| 완전 구움 | 기존 완성 PNG 그대로 | 원본 품질 유지 |

알파>250인 공유 앞면 **281,038픽셀**은 네 상태 모두 원본 대비 변경 **0**입니다. 이는 앞면 하트·주름·바닥을 고정하는 데이터/좌표 방식 검증입니다. **컵 전체 외곽과 안쪽이 완성됐다는 뜻이 아닙니다.** 원본 케이크에 가려진 종이컵 뒤·안쪽 픽셀은 이 이미지에 존재하지 않습니다. 경계가 톱니처럼 보이거나 이음새가 남으면 실패라는 요청에 따라 보류합니다.

`B-four-states.png`와 `cup-empty/filled/risen/baked.png`는 실패 부분을 포함한 시험 증거입니다. 정식 에셋이 아닙니다.

## C — 트레이와 독립 상태

승인된 빈 3구 트레이에 동일한 기존 완성 컵 PNG 3개를 배치했습니다.

| ID | 트레이 좌표의 발밑 앵커 | 공통 배율 |
|---|---|---:|
| cup-1 | 393,680 | .45 |
| cup-2 | 902,680 | .45 |
| cup-3 | 1404,680 | .45 |

컵 원본의 발밑 `(623,1082)`를 기준으로 계산합니다. 같은 크기, 가로 겹침 없음, 기본 배치에서 트레이 안에 들어가는 모습을 확인했습니다. 트레이 y=690 이후 원본을 마지막에 다시 그려 앞쪽 영역을 보호합니다. 현재 컵 발밑은 y=680으로 보호선 아래를 침범하지 않으며, **전용 곡선 앞면 마스크가 완성된 것은 아닙니다**. 더 깊이 들어가거나 컵 크기가 바뀌는 제품 연출에는 별도 가림 검수가 필요합니다.

세 ID 각각 `{id, cream, bake}`를 별도 객체로 관리합니다. 선택 컵에만 기존 딸기/바닐라 크림을 적용·제거하고 나머지 ID의 디자인이 유지됨을 확인했습니다. localStorage/sessionStorage를 저장하지 않습니다. 기존 스프링클·접시는 그대로 재사용 가능하지만 이번 시험에는 새 꾸미기 기능이나 PNG 저장 기능을 추가하지 않았습니다.

## D — 그룹 이동과 3초 굽기

트레이를 하나의 그룹으로 이동합니다. Pointer Events 드래그 또는 이동 버튼으로 점선 검사 위치에 넣습니다. **점선은 위치 검사 표시이며 오븐 원화가 아닙니다.** 실제 오븐 문 열기·닫기를 이번 시험에서 구현했다고 보고하지 않습니다.

트레이 로컬 좌표와 세 ID를 그대로 두고 그룹의 이동/균일 배율만 바꿉니다. 그룹이 들어간 뒤 3000ms 동안 기존 반죽 표면과 기존 케이크 내용물만 변화시킵니다. 마지막에는 원본 완성 PNG와 동일한 모습을 사용하며 새로운 완성 피사체를 생성하지 않습니다. 매 프레임의 실제 경과 시간을 사용하고 문서가 숨겨진 동안은 진도를 멈춥니다.

- 위치/ID/앞면 픽셀 고정: 자동 검증 통과.
- 실제 화면에서 세 컵 앞면의 고정 표본 3,600픽셀(RGBA 14,400채널)을 굽기 전·중·후 비교: 변화 없음.
- 자연스러운 생반죽→구움 품질: **실패**. 컵 내부가 없고 처음부터 구운 질감의 내용물을 축소해 사용하므로 실제 반죽이 부푸는 고품질 원화와 다릅니다. 그림이 준비됐다고 주장하지 않습니다.

`D-before.png`, `D-middle.png`, `D-after.png`, `D-group-inside.png`, `baking-checks.json`을 남겼습니다. JSON의 `durationMs`는 버튼 클릭·자동 확인·스크린샷을 포함한 테스트 관측 시간입니다. 애니메이션 진도는 `elapsed=0~3000`으로 별도 관리하므로 관측 시간이 약 4초라고 4초 굽기로 바뀐 것은 아닙니다.

## 검사 범위

독립 시험 8개: 에셋 로딩/원본 해시/저장 무변경, 재료 투입·거품기, 앞면 픽셀, 독립 ID, 포인터 그룹 드래그, 3초 변화/화면 픽셀, 반응형, CDP 실제 터치 이벤트·취소 처리입니다. 자동 검사는 기술적 조건만 확인합니다.

태블릿 1280×800·1280×720, 스마트폰 360×800·800×360에서 가로 넘침과 조작 요소 접근을 검사했습니다. 스마트폰은 세로 스크롤로 긴 시험 설명을 볼 수 있습니다. **실제 삼성 갤럭시 기기는 미검증**이며 Chromium 크기 모사/터치 이벤트 시험입니다.

독립 시험 **8개 통과**, 비교 문구 보완 후 해당 픽셀 검사 **1개 재확인 통과**입니다. 기존 컵케이크 17개·레이아웃 보완 5개·피자 전체 터치 흐름 1개·햄버거 전체 터치 흐름 1개·홈의 다섯 게임 진입/복귀 1개, 총 **25개 회귀 테스트 통과(2.2분)**입니다. 별도 결과 로그 `regression.log`, 요약 `test-summary.json`을 참고하세요. 타입 검사·운영 빌드·Pages 경로 검증도 통과했으며 기존 큰 청크 경고만 남습니다. 검사 과정에서 기존 테스트가 재생성한 과거 캡처는 원상 복구하고, 이번 문서/시험 코드만 커밋합니다. 전체 게임 전용 테스트 전체를 실행한 것으로 확대 해석하지 않습니다.

node node_modules/typescript/bin/tsc --noEmit

## 최소 추가 자료 — 3장만 우선 검수

이번 실패를 해결하기 위해 재료 4종·여러 굽기 상태를 대량 재제작할 필요는 없습니다. 다음 **3장**을 우선 권장합니다. 이 중 앞면은 새로 그리는 그림이 아니라 기존 원본에서 정확하게 분리하는 작업입니다.

1. **`cup-wrapper-front.png` 1장:** 1254×1254 RGBA, 기존 완성 컵의 분홍 앞면·하트·주름·흰 물결 입구·바닥 픽셀을 손상 없이 분리. 내용물/뒤쪽 제외. 같은 원본 좌표 유지. 이음새 없는 앞면 마스크가 목적입니다.
2. **`cup-wrapper-back-inside.png` 1장:** 같은 1254² 좌표에 그 앞면과 맞는 뒤쪽/안쪽 빈 컵만. 앞면과 합쳐 자연스러운 빈 컵이 되게 제작. 이 영역은 기존 완성 이미지에서 케이크에 가려져 복원 원화가 필요합니다.
3. **`mixing-bowl-empty.png` 1장:** 기존 반죽 볼과 외곽·하트·받침·시점·위치가 동일한 1254² 빈 볼. 내용물만 제거/복원하며 볼을 새 디자인으로 그리지 않기.

이 3장이 맞으면 기존 반죽 표면·케이크 내용물·카드 질감으로 다시 합성 검수를 진행합니다. **3장만 있으면 반드시 모든 시각 문제가 해결된다는 보장은 하지 않습니다.** 먼저 대표 빈 컵/반죽/구움 전환과 빈 볼에 대한 재검수 후 정식 3개 동시 제작 여부를 결정해야 합니다. 현재 정식 2차 전체 개발 준비 완료로 보고하지 않습니다.

## 변경 범위

새 폴더 `experiments/cupcake-reuse/`와 이번 보고 폴더만 추가합니다. 운영 src/public 원본, 기존 게임, 저장 키, 게임 등록, 기존 vite/Pages/PWA 설정을 변경하지 않습니다. 검수된 5종은 부모 브랜치 그대로입니다. 재사용 가능한 정식 이미지는 기존 원화 + 이미 승인된 5종이며, 이번 시험에서 새 최종 원화를 확보한 것은 아닙니다.
