# 요리놀이 2.0 — 햄버거 시험판

최신 main `b2546aa`와 병합된 피자 PR #22를 기준으로 독립 구현했습니다. 기존 홈의 요리놀이 연결, 피자 코드·에셋·저장 데이터는 변경하지 않습니다. 자동 병합·배포는 하지 않습니다.

## 실행과 화면

개발 서버 또는 빌드 미리보기에서 `/kids-game-playground/prototypes/cooking-v2/burger/`를 엽니다. GitHub Pages에서는 이 PR을 사용자가 병합하고 수동 배포한 뒤 같은 경로로 실행합니다. 아직 배포되지 않은 기능입니다.

1. 패티 굽기: 생패티를 팬으로 끌어 놓거나 '팬에 올리기'를 누릅니다. 뒤집개를 선택하고 패티를 누르거나 팬으로 끌어 뒤집습니다. 양면을 익혀 다음 단계로 갑니다.
2. 재료 고르기: 9종 중 원하는 재료를 선택하거나 취소합니다. 정답이나 필수 재료는 없습니다.
3. 쌓기: 하단 재료를 위로 끌거나, 재료를 고른 뒤 햄버거를 누릅니다. 같은 재료도 반복할 수 있습니다. '재료 빼기'에서는 아래 목록에 층 번호가 나타나 가려진 층도 제거할 수 있습니다.
4. 완성: 실제 만든 재료 구성 위에 윗빵만 추가합니다. 다시 쌓기, PNG 저장, 요리 선택 복귀가 가능합니다.

하단 진열대는 가로 스크롤과 양쪽 화살표를 함께 제공합니다. 터치의 가로 이동은 스크롤, 위쪽 이동은 재료 드래그로 구분하고 취소된 포인터는 재료를 추가하지 않습니다. 정확한 좌표 대신 넓은 조리 영역을 허용합니다. 키보드 선택과 Enter/Space 조작도 제공합니다.

## 에셋 검사와 처리

공식 시안 A/B/C와 원본 PNG 24종을 직접 확인했습니다. [원본 모음](original-assets.png), [원본 크기·알파·SHA256 전체 검사표](asset-audit.json)를 함께 제공합니다. 모두 실제 투명 배경이 있으나 낮은 알파의 외곽 색 점과 불필요한 여백이 있어, 원본을 보존하고 가공본만 별도 제작했습니다.

가공 시 알파 64 초과 영역의 경계를 기준으로 자르고, 알파 20 미만은 제거, 244 초과는 불투명 처리했습니다. 음식 자체를 새 도형으로 그리거나 시안에서 잘라 쓰지 않았습니다. 원본 SHA256을 자동 검사합니다.

| 사용 | 에셋 |
|---|---|
| 굽기 | patty-raw, patty-cooked, frying-pan, spatula |
| 기본/마무리 | bun-bottom, bun-top, plate |
| 쌓기 9종 | patty-cooked, cheese-stack, lettuce-stack, tomato-stack, onion-group, pickle-group, bacon, egg, mushroom-group |
| 선택 목록 | 위 재료와 cheese, lettuce, tomato 원본의 가공 썸네일 |
| 소스 조작 | ketchup / mayonnaise / mustard bottle 3종 |
| 검사·예비 | 소스 bowl 3종은 가공·로딩 검사하지만 음식 위에는 사용하지 않음 |

총 24종을 검사·가공·로딩하며 실제 화면은 그중 21종을 사용합니다. 새 7종의 큰 여백도 정리했습니다. 생패티 1254×1254와 구운 패티 509×352는 픽셀 크기가 다르므로 동일한 표시 상자와 중심에 맞춰 교차 합성합니다.

## 조리·쌓기 구조

양면 굽기는 첫 면 1.8초, 뒤집기 0.55초, 반대 면 1.8초입니다. 첫 면이 익으면 뒤집기를 기다리며 타지 않습니다. 조금 일찍 뒤집어도 진행할 수 있습니다. 주방을 떠나거나 창이 숨겨졌을 때와 초기화 확인창에서는 굽기가 멈춥니다. 김과 뒤집기 회전, 익은 정도 표시로 소리 없이도 진행을 알 수 있습니다. 소리는 짧은 조작음·완료음이며 실제 지글지글 녹음은 아닙니다.

각 재료는 고유 ID, 종류, 순서를 저장하고 표시 폭·높이·두께·겹침 보정값을 데이터로 관리합니다. 층마다 바닥 높이를 올려 계산하고 부드럽게 정렬합니다. 순서를 강제하지 않으며 동일 재료를 반복할 수 있습니다. 최대 16층이고, 높은 구성은 윗빵까지 들어갈 공간을 미리 계산해 음식 전체를 축소합니다. 층 제거 후 되돌리면 ID와 순서가 복원됩니다.

완성 시 다른 햄버거 그림으로 교체하지 않습니다. 화면과 PNG 모두 같은 `layout()` 결과를 사용합니다. PNG는 투명 배경 1400×1400이며 햄버거와 접시만 포함합니다. 일부 원본은 작은 해상도라 PNG를 크게 확대하면 선명도 한계가 있습니다.

전용 저장 키는 `kids-game-playground:v1:game:cooking-v2:burger:prototype:r1`입니다. 단계·굽기·선택 재료·층별 순서와 개수·소스 선택/사용 기록·완성 여부·소리·최근 60개 편집 이력을 자동 저장합니다. 손상된 데이터는 이 게임의 새 상태로만 대체합니다. 초기화는 확인 후 이 게임만 새로 시작하고, 완료 후 요리 선택으로 돌아가면 '만들기 시작' 상태가 됩니다. 저장 차단 시 안내하고 게임은 계속합니다.

## 소스의 구현 범위와 필요한 이미지

병 3종 선택, 터치/드래그, 병을 기울이는 동작, 사용한 소스와 당시 층 기록까지 구현했습니다. **음식 위 소스 질감은 미구현**입니다. 화면에도 '소스 모양은 준비 중'이라고 표시합니다. 품질을 낮추는 굵은 선이나 도형으로 대체하지 않았고 PNG에도 가짜 소스를 넣지 않습니다.

추가 제작 권장 자료:

- 케첩·마요네즈·머스터드가 층 위에 얇게 뿌려진 투명 PNG 각 1종 이상, 약 1024×512. 빵·패티와 같은 사선 시점, 따뜻한 조명, 부드러운 윤기, 자연스러운 가장자리. 음식/병/접시/그림자 배경은 제외.
- 양파·피클·버섯의 더 낮은 측면 시점 버전. 현재는 여러 조각이 묶인 에셋이므로 1회 놓기 = 한 묶음입니다. 폭과 세로 비율 보정으로 쌓지만 모든 조합의 입체 교차를 표현하지는 못합니다.
- 향후 고해상도 PNG 품질을 높이려면 아랫빵·구운 패티·접시·기존 토핑을 긴 변 1200px 이상으로 같은 시점에서 제작하는 것이 좋습니다.

## 시안과 실제 화면 비교

분홍 주방, 밝은 나무 조리대, 크게 보이는 음식, 하단 재료 진열대와 파스텔 버튼을 유지했습니다. 실제 화면은 임의의 재료 순서와 화면 크기에 맞춰 합성하므로 정적인 시안의 햄버거와 구성·배치가 달라집니다. 별도 가스레인지 에셋이 없어 팬을 조리대 위에 표시하며 시안의 레인지를 잘라 붙이지 않았습니다. 소스 병은 하단 소스 탭으로 모아 좁은 화면에서도 음식 공간을 확보했습니다.

양상추·치즈·토마토는 낮은 시점의 stack 에셋을 사용하고, 나머지 재료는 폭·두께·겹침을 조정했습니다. 3층·7층·완성 화면에서 공백 없이 이어지는 모습과 같은 재료 구성을 시각적으로 확인했습니다. 다만 원본마다 시점이 완전히 같지는 않아 실제 3D 음식 수준의 가림·변형을 보장하지 않습니다.

## 검증

햄버거 전용 12개 테스트 통과: 원본 24종 해시/디코딩/알파, 양면 굽기와 되돌리기, 실제 터치 드래그, 자유 순서/반복/16층, 제거/복원, PNG, 5개 화면 크기, 가로 스크롤과 드래그 취소, 소스, 저장·초기화·피자 키 보존, 오프라인·키보드·저장 차단을 검사했습니다.

TypeScript 검사, Vite 빌드, GitHub Pages 경로 검증이 통과했습니다. 빌드에는 기존 큰 번들 크기 경고가 남아 있습니다. 기존 게임 소스는 변경하지 않았고 전체 자동 테스트 233개가 10.9분에 모두 통과했습니다(햄버거 12개 + 기존 221개). 기존 홈·색칠놀이·요리놀이·코디놀이·벽돌깨기·짝꿍카드·요리놀이 2.0 피자를 포함합니다. 오프라인은 최초 온라인 로딩과 서비스워커 설치가 완료된 뒤 가능합니다. 브라우저가 캐시를 삭제하거나 설치 중 네트워크가 끊기면 다시 온라인 접속이 필요합니다.
