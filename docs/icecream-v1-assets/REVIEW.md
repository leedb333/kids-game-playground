## 가공 및 알파 검사

단순 사각형 crop만 하지 않았다. 분리 영역에서 alpha≥24 연결 성분을 식별하고 떨어진 작은 잡티를 제외했다. 선택 성분 외곽의 2픽셀 범위는 기존 반투명 경계를 보존했다. cone의 이웃 바닐라 조각, candy의 초코과자 조각, cookie의 보라색 사탕 조각은 개별 제거 후 재검수했다. 새 외곽선/음식 도형을 그리지 않았다. 가로·세로 동일 배율 적용, 강제 변형 없음.

스쿱 9종: 보이는 폭 목표 800px, 수평 중심 512, 바닥 기준 920. 실제 alpha>20 경계는 보간 때문에 대략 ±2px 차이. 원본별 실루엣과 바닥 주름 모양 자체는 서로 다르며 동일 모양으로 변형하지 않았다. asset-audit.json에 각 PNG 해상도·투명/반투명 픽셀 수·보이는 경계·최종 해시 기록. 모두 실제 투명 픽셀을 가지며 가장자리 잘림 없음. 반투명 원화의 알파값은 불투명하게 덮지 않았다.

원본 스쿱은 약 332~343×310~318px. 1024 출력은 보관 좌표계 통일이지 디테일 증가가 아니다. 실제 게임 표시 폭은 가능하면 250~330 CSS px, 3스쿱/화면 크기에 따라 균등 축소를 권장한다. 2배 DPR에서 원본 이상의 선명도는 보장할 수 없다.

## 토핑과 남은 제약

- 체리/하트웨하스는 독립 스프라이트로 터치·드래그 가능. 초코과자는 원본의 두 롤이 접촉한 묶음으로 보존했다. 한 롤 단위가 꼭 필요하면 오른쪽 롤의 가려진 경계 수작업 분리가 추가로 필요하다. 이 묶음을 두 개 독립 롤로 검수 통과했다고 주장하지 않는다.
- sprinkles/candy는 각각 작은 조각의 묶음 스프라이트이다. 사탕의 서로 떨어진 별/구슬은 연결 성분별로 개별 추출 가능하다. 스프링클은 서로 붙은 막대가 많아 자동 성분 분리만으로 모든 막대를 온전히 얻을 수 없다. 떨어진 막대만 재사용하거나 Canvas로 둥근 막대를 그리는 방식이 반복 뿌리기에 더 안정적이다. 현재 묶음 전체를 손가락마다 찍으면 과밀해진다.
- 시럽은 합성 가능한 완성형 PNG이나 평면 장식처럼 보일 수 있다. 상단 스쿱 폭의 55~65%로 제한하고 아이스크림 알파에 클리핑할 것. 손가락 경로를 따르는 흐르는 시럽은 이 PNG만으로 불가능하다. 필요 시 Canvas 곡선·광택·그림자를 별도 구현하는 편이 낫다. 여기서는 실제 게임의 표면 워핑/마스킹 기능까지 검증하지 않았다.
- 공식 시안의 컵은 아이스크림 로고, 추출 컵은 하트 로고로 다르다. 원본 디자인을 임의 변경하지 않았다.
- 시안 전체 배경 사용 금지. 이후 UI를 분리 구현하고, 비어 있는 매장/카운터 배경이 필요하면 **배경 1장**만 별도 제작. 이번에는 생성하지 않았다.

## 검증 범위

어두운 배경 contact-dark.png에서 원본 반투명 가장자리·이웃 픽셀·색을 확인했다. 밝은 배경 compositions.png에서 8조합의 접촉·겹침·크기·전체 높이를 확인했다. 원본 해시, 최종 PNG 알파·해상도 검사 수행. 원본은 보존했다. 게임 코드가 없는 에셋 작업이므로 게임 빌드·터치 조작·PNG 다운로드 기능·실제 갤럭시탭 플레이·토핑 개수 제한은 이번 검수 대상이 아니며 실행했다고 보고하지 않는다.

최종 보완으로 10맛 스쿱 쌓기 시험판 개발 시작 가능. 초기 붉은 후보는 기록으로만 보존하고 새 승인 원본을 사용했다. 완성형 PNG 저장은 동일 합성 좌표를 사용하면 된다. main 병합·배포는 수행하지 않는다.
