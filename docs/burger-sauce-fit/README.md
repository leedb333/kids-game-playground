# 햄버거 소스 윗면 배치 개선

기준: PR #23이 병합된 최신 main `c0670fc`. 새 브랜치: `fix/burger-sauce-surface`. 기존 PNG를 그대로 재사용하고 **실제 게임 코드 변경은 `src/games/cooking-v2/burger/model.ts`의 소스 레이아웃 계산에 한정**했습니다. 저장 구조·UI·음식 좌표·그림은 바꾸지 않습니다. 신규 테스트와 이 비교 자료만 추가합니다.

## 노란 영역의 구분

렌더링 코드를 직접 확인했습니다. 넓고 평평한 한 장 모양은 `cheese-stack.png` 치즈이고, 반복된 노란 지그재그는 `sauce-mustard-drizzle.png` 머스터드입니다. [소스 없는 치즈 진단 화면](before/cheese-diagnostic.png)에는 `cheese-stack`만 있고 drizzle은 0개입니다. 음식인 치즈의 크기와 위치는 이번에 변경하지 않았습니다.

## 원인과 변경 계산

| 항목 | 수정 전 | 수정 후 |
|---|---|---|
| 소스 폭 | 재료 폭 × 저장 배율, 보통 82~87% | 저장 배율 × 0.65를 표시용으로 적용, 보통 53.3~56.6% |
| 표시 폭 안전 범위 | 저장 배율 70~90% 허용 | 재료 폭 40~65% 안으로 제한; 기존 유효 데이터는 45.5~58.5% |
| 소스 높이 | 표시 폭 × 0.20 | 표시 폭 × 0.10; 기존 표시 높이의 32.5% |
| 세로 중심 | 재료 이미지 높이의 약 78% + 보정 | 재료별 윗면 중심 32~43% + 작은 분산 |
| 기울기 | 저장 각도 전체 | 저장 각도 × 0.35 |
| 반복 배치 | 거의 같은 가로 위치, 3회마다 유사한 세로 보정 반복 | 고유 ID로 좌우·앞뒤의 작은 분산을 결정 |

재료의 실제 표시 상자(`base.x/y/width/height`)는 기존 높이·두께·겹침 계산 결과입니다. 소스는 이 상자 안의 윗면을 기준으로 배치합니다. 윗면 기준은 아랫빵·치즈 32%, 패티·토마토 38%, 양상추·양파·피클·달걀 40%, 베이컨 42%, 버섯 43%입니다. 서로 다른 PNG 시점에 맞춰 소스 기준만 구분했습니다.

반복 분산은 `fract(id × 0.61803398875)`와 `fract(id × 0.41421356237)`로 계산합니다. 가로는 재료 폭의 약 ±13%, 세로는 재료 높이의 약 ±6%에 기존 손가락 보정값을 작게 더합니다. 음식 가로 경계 안에 남으며, 무작위 값이나 현재 목록 인덱스를 사용하지 않습니다. 그래서 같은 저장을 다시 열거나 중간 소스를 제거해도 **다른 소스의 위치가 바뀌지 않습니다**. 되돌리면 이전 소스가 같은 위치로 돌아옵니다.

## 보존한 동작

- 패티 굽기, 재료 9종의 크기·높이·자동 정렬, 16층 제한을 그대로 유지합니다.
- 소스의 종류·횟수·연결 층·ID·저장 배율·회전과 저장 키/version을 변경하지 않습니다. 이전 저장도 새로운 표시 비율로 읽을 뿐 데이터를 덮어쓰지 않습니다.
- 소스는 기존처럼 지지하는 재료 직후, 후속 재료 이전에 그립니다. 새 치즈·다른 재료·윗빵이 소스를 자연스럽게 덮습니다. 가려진 소스를 앞면으로 옮기지 않습니다.
- 재료 제거 시 아래 층으로 연결하고, 제거·되돌리기·저장·이어하기 처리를 유지합니다.
- 화면 SVG와 PNG는 동일한 `layout()` 계산을 그대로 사용합니다. PNG는 1400×1400 투명 배경이며 음식과 접시만 포함합니다.
- 다른 게임, 통합 홈, 피자, 원본/가공 PNG, 배포 설정은 수정하지 않습니다.

## 검증

타입 검사, Vite 빌드와 GitHub Pages 경로 검사를 통과했습니다. 비교 8개와 신규 모델 검사 2개를 포함해 햄버거 관련 테스트 33개가 통과했습니다. 신규 검사는 9종 재료·아랫빵의 폭/높이/윗면 경계, 20회 반복 배치의 서로 다른 위치, 소스 제거 후 이웃 위치 고정, 기존 저장 호환, 재료 제거/복원, 재료 좌표 불변과 층 순서를 검사합니다. 기존 테스트의 실제 터치, 16층, 저장·오프라인, 완료 PNG의 화면 픽셀 비교도 통과했습니다.

전체 자동 테스트 254개가 11.9분에 모두 통과했습니다(기존 244개 + 신규 10개). 홈·색칠놀이·요리놀이·코디놀이·벽돌깨기·짝꿍카드·요리놀이 2.0 피자의 회귀 검사를 포함합니다. 빌드에는 기존 큰 번들 경고가 있으며 이번 변경에서 번들 분할을 바꾸지는 않았습니다. 실제 갤럭시탭·스마트폰 기기는 미검증이며 Chrome의 화면 크기/터치 시뮬레이션 결과입니다.

## 추가 이미지 필요 여부와 한계

이번 범위는 기존 PNG 3종의 축소·세로 압축·위치·각도 보정으로 개선할 수 있어 **필수 추가 이미지는 없습니다**. 소스의 반투명 가장자리·윤기와 음식 이미지는 그대로 유지했습니다. 소스는 2D 이미지여서 울퉁불퉁한 채소 표면을 따라 실제로 굽어지거나 흐르지는 않습니다.

향후 더 사실적인 표현을 원하면 가는 소스 줄이 낮은 사선 시점으로 놓인 투명 PNG(소스별 2~3패턴, 약 1200×300, 앞쪽으로 떨어지는 큰 방울 없이, 기존과 같은 따뜻한 조명)를 제작하면 과도한 세로 압축을 줄일 수 있습니다. 이번 작업에서는 새 이미지로 교체하지 않았습니다.
