## 크기와 입력 검수

모든 값은 Chromium의 CSS 픽셀입니다. 간격은 그림 자체의 모서리 사이이며 세로 화면에서는 그림 제목을 포함합니다.

| 모의 화면 | 한 장 크기 | 그림 간격 | 패널 폭 | 버튼 크기 | 나비 판정 1배 | 나비 판정 2배 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 태블릿 1280×800 | 566.4×566.4 | 7 | 107.5 | 107.5×82 | 74.1×47.9 | 148.2×95.8 |
| 태블릿 1280×720 | 566.4×566.4 | 7 | 107.5 | 107.5×82 | 74.1×47.9 | 148.2×95.8 |
| 스마트폰 가로 800×360 | 244×244 | 7 | 80 | 80×52, 확대 80×64 | 31.9×20.6 | 63.8×41.3 |
| 스마트폰 세로 360×800 | 292×292 | 30 | 하단 292 | 70×64 | 38.2×24.7 | 76.4×49.4 |

판정 치수는 경계 상자이며 실제 판정은 타원이나 다각형입니다. 2배 수치는 확대된 영역의 치수입니다. 확대 후 그림 가장자리 밖으로 잘린 영역은 화면을 움직여 볼 수 있습니다. 1배에서 두 그림의 크기와 1:1 비율이 일치했습니다. 네 화면에서 사진과 버튼의 잘림을 확인했고, 2배에서 두 그림과 표시 위치가 함께 움직였습니다. 마우스 드래그, 모바일 터치 드래그, 멀티터치 취소, 1배 세로 스크롤을 검사했습니다. [일곱 정답의 양쪽 표시 및 판정 치수](measurements.json)

작은 나비 자체의 시각적 크기는 판정 타원보다 작습니다. 스마트폰 가로 1배에서는 정밀 터치가 어려울 수 있고 2배에서는 해당 위치까지 이동이 필요합니다. 실제 갤럭시 기기의 가독성·터치 감도와 어린이의 체감 난이도는 실기 검수가 필요합니다.

## 에셋과 확장

D01은 사용자 업로드 커밋 ceabb32의 파일을 그대로 사용합니다. 게임용 두 장은 1254×1254이고 썸네일은 384×384입니다. 세 파일의 RIFF 청크는 무손실 WebP를 뜻하는 VP8L입니다.

| 파일 | 바이트 |
| --- | ---: |
| D01-original.webp | 2,530,252 |
| D01-modified.webp | 2,533,928 |
| D01-thumbnail.webp | 293,972 |
| D01.json | 17,027 |
| 합계 | 5,375,179 |

SHA-256으로 네 업로드 파일을 확인했습니다. 브라우저에서 디코딩한 두 이미지의 RGBA를 비교해 JSON에 기록된 일곱 편집 사각형 바깥의 차이가 0픽셀임을 확인했습니다. 원본과 변경본 각각 1254×1254 좌표를 순회한 검사에서도 복수 판정에 포함된 표본은 0개였습니다. Work의 별도 정밀 편집 마스크 파일은 업로드 목록에 없어 독립 픽셀 비교에는 JSON의 사각형을 사용했습니다. [픽셀 비교 기록](pixels.json)

등록 스키마는 1.0.0이며 D01 데이터 버전은 D01-1.0.0입니다. 좌표 원점은 이미지 좌상단입니다. 두 그림의 터치 및 표시 영역을 각각 읽습니다. 실제 D01은 타원과 다각형을 사용하며 로직은 원도 지원합니다. 다각형은 경계까지 인정합니다. 공은 두 그림에서 각기 다른 타원으로 판정하고 표시합니다. 힌트는 JSON의 힌트 영역을 1.32배 확대해 3초간 표시합니다. 영역이 없는 후속 데이터는 대응하는 표시 영역을 사용합니다.

추가 콘텐츠는 같은 이름 규칙의 WebP 3개와 JSON을 해당 ID 폴더에 두고 카탈로그에 등록합니다. 게임은 6~10개의 정답 수를 처리합니다. 데이터 버전과 활성화 여부, 최초 오프라인 준비 대상 여부는 콘텐츠별로 관리합니다. [콘텐츠 카탈로그](../../src/games/spot-the-difference/catalog.ts)

## 저장과 오프라인

D01 진행 키는 `kids-game-playground:v1:game:spot-the-difference:r1:D01`입니다. 버전·전체 정답 수·발견 ID·완료 이력을 저장하며 현재 플레이의 완료 여부는 발견 수와 전체 수를 비교해 구합니다. 발견 시점에 저장하고 둘의 발견 표시를 갱신합니다. 마지막 정답을 저장하고 1.5초 뒤 완료 화면을 표시합니다. 다시 하기는 그림 선택으로 돌아갑니다. 재도전은 완료 이력을 유지하고 현재 발견 목록을 비웁니다. 진행 중의 새로 시작하기는 확인을 거칩니다.

그림 선택 화면의 요청은 썸네일만 사용합니다. 플레이 진입 시 JSON과 두 원본 크기 WebP를 열고 양쪽 디코딩이 끝나면 입력을 받습니다. 별도로 PWA 최초 온라인 설치 중에는 D01 사전 캐시가 네 파일을 내려받습니다. 최초 사용자도 캐시 설치와 제어가 끝나면 오프라인에서 D01을 시작할 수 있습니다. 이전 설치 사용자는 온라인에서 새 버전을 받은 뒤 기존 놀이터 탭을 닫아 새 서비스 워커가 활성화되면 오프라인에서 사용할 수 있습니다. 독립 색칠·요리 앱의 범위와 캐시는 유지됩니다.

같은 크기의 그림 10세트는 데이터와 이미지만 약 53.75 MB가 예상됩니다. 카탈로그에 등록해도 오프라인 대상을 지정하지 않은 콘텐츠는 초기 서비스 워커 사전 캐시에 들어가지 않습니다. 후속 세트의 오프라인 다운로드 정책은 전체 콘텐츠 제작 단계에서 검증이 필요합니다.
