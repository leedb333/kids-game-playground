# 요리놀이 2.0 — 피자 조작 시험판 1차

## 실행과 작업 범위

- 별도 화면: `/kids-game-playground/prototypes/cooking-v2/` (`index.html` 주소도 가능).
- 개발 서버에서는 `node node_modules/vite/bin/vite.js --host 127.0.0.1` 실행 후 같은 경로로 이동한다.
- 배포 빌드에는 독립 HTML 진입점으로 포함한다. PR만으로 공개 배포되지는 않는다.
- 통합 홈의 카드, 기존 요리놀이와 나머지 네 게임, 기존 저장 키는 수정하지 않았다.
- 기존 파일 변경은 `vite.config.ts`뿐이다. 독립 HTML 빌드 입력과 그 HTML의 오프라인 캐시 주소를 추가했다.
- 반죽 펴기와 오븐 굽기는 구현 범위에 포함하지 않는다. 완료 화면에서도 아직 굽지 않은 시험판임을 알린다.

## 실제 조작

### 1. 소스 바르기

- 숟가락은 처음부터 선택되어 있다. 숟가락을 도우로 끌어 놓거나, 도우 위를 손가락으로 문지른다.
- 손가락 경로를 흰색 **비표시 마스크**에 기록하고 `source-in` 합성으로 제공된 토마토소스 질감만 드러낸다. 화면에 빨간 선이나 흰색 마스크를 그리지 않는다.
- 둥근 브러시 반경 84/1024, 둥근 연결부를 사용한다. 도우 밖으로 나갔다 돌아오면 경로를 끊어 불필요한 직선을 방지한다.
- 안쪽 타원 중심 (512,512), 반경 (407,392)에 제한하여 가장자리 반죽을 남긴다.
- 128×128 별도 마스크에서 실제 칠한 면적을 계산한다. 65% 이상이면 토핑 단계로 갈 수 있다.
- 단계 이동 후에도 원래 칠한 소스와 빈 부분이 그대로 유지된다. 자동으로 전부 칠하지 않는다.

### 2. 토핑 올리기

- 재료를 고른 뒤 피자를 터치하거나 하단 재료를 피자로 끌어 놓는다. 재료 목록은 이동하지 않는다.
- 페퍼로니와 버섯은 원본에서 추출한 1조각씩 반복 배치한다. 피자 지름 기준 약 15~16% 폭이며 작은 회전·크기 차이를 둔다.
- 치즈는 한 번에 작은 가닥 10개를 분산 배치한다. 문지르면 이동 간격에 따라 더 뿌린다. 큰 원형 치즈 한 장을 올리지 않는다.
- 모든 토핑은 `id, kind, x, y, rotation, scale, variant, group`으로 저장한다. 화면 크기와 무관한 1024 기준 좌표다.
- ‘옮기기’: 기존 토핑을 잡고 이동. ‘빼기’: 토핑을 누르면 제거. 치즈는 한 번 뿌린 묶음 단위로 제거된다.
- ‘되돌리기’는 손가락을 누르고 뗀 한 동작 단위다. 길게 치즈를 뿌렸어도 한 번에 되돌린다. 잘못 떨어뜨리거나 시스템이 터치를 취소하면 확정하지 않는다.
- 안전한 반복 조작을 위해 현재 토핑은 치즈 720가닥, 기타 100조각까지 표시한다. 저장 용량·저사양 기기의 렌더링 부담을 제한하기 위한 상한이다.
- 토핑을 올리지 않아도 원하는 때 ‘시험판 완료’를 누를 수 있다. ‘더 꾸미기’로 되돌아올 수 있다.

## 화면과 저장

- 별도 HTML 페이지에서만 스타일을 적용한다. 상단은 짧은 제목·2단계·홈·소리, 중앙은 큰 도마와 피자, 하단은 재료와 조작 버튼이다.
- 원본 음식 이미지를 표시하고, Canvas는 합성·마스크·배치만 담당한다. 단순 도형 음식으로 대체하지 않는다.
- Pointer Events와 pointer capture를 사용한다. 조작 중 페이지 스크롤·텍스트 선택을 차단한다. 마우스도 지원한다.
- 버튼 선택 후 피자에 Enter/Space로 배치하는 키보드 보조 조작도 제공한다.
- 독립 저장 키: `kids-game-playground:v1:game:cooking-v2:pizza:prototype:r1`.
- 단계·소스 경로·토핑 동작을 저장한다. 새로고침하면 이어진다. 비정상 데이터는 해당 시험판만 기본값으로 복구하고 다른 게임 저장 데이터는 읽거나 지우지 않는다.
- 저장이 차단되면 안내하고 놀이를 계속한다. 음식 로딩 실패 시 안내와 재시도 버튼을 표시하며 임시 도형으로 대체하지 않는다.
- 빌드된 전용 HTML의 슬래시 주소와 명시적 index.html 주소, 가공 이미지를 기존 캐시 목록에 추가한다. 온라인으로 캐시 설치 완료 후 시험판도 오프라인 재접속 가능하다.

공식 시안과 같은 따뜻한 분홍·나무 주방 분위기, 큰 원형 음식, 부드러운 버튼을 목표로 했다. 다만 주어진 배경·음식은 시안과 동일한 원화가 아니다. 시안의 그릇·장갑·빨간 오븐은 이번 에셋에 없으므로 임의 그래픽으로 대체하지 않았다. 음식은 시안보다 사실적인 광택이 강하고, 배경은 동화풍이다. 완전히 같은 그림체라고 평가하지 않는다.

소스의 밝은 반사는 원본 질감이다. 마스크가 비어 생기는 흰 구멍과 구분해야 한다. 치즈 가닥은 무더기에서 추출했으므로 일부 겹친 질감이 남는다. 독립 가닥 원화가 있으면 더 자연스럽게 개선할 수 있다. 버섯·페퍼로니의 잘라낸 가장자리도 전용 단일 조각 에셋보다 정밀도가 낮다.

## 검증

로컬 검증 결과: TypeScript 검사, Vite 프로덕션 빌드, GitHub Pages 경로 검사 모두 통과. 기존 197개 + 시험판 13개를 합친 전체 210개 테스트 통과(9.0분). 마지막 작은 화면 버튼·키보드 보조 조작 수정 후 시험판 13개를 다시 실행하여 모두 통과(46.3초). 기존 번들의 큰 청크 경고는 남아 있으나 빌드 실패는 아니다.

`tests/cooking-v2.spec.ts`는 원본 8종 로딩·해시, 파생 이미지 로딩, 소스 면적/진행 제한, 크러스트 밖 픽셀 불변(렌더링 반올림 오차 3/255 허용), 단계 간 보존, 터치/마우스 드래그, 위치/회전/크기, 치즈 뿌리기, 이동/제거/되돌리기, 잘못 놓기, pointercancel, 초기화 확인, 저장/재접속, 저장 차단, 로딩 실패, 오프라인, 5개 화면 크기를 확인한다. 기존 테스트도 전체 실행한다.

화면 캡처와 터치 테스트는 Windows Chrome의 화면 크기·터치 입력 모사 결과다. 실제 갤럭시탭·갤럭시 스마트폰의 손가락 사용감, GPU 성능, 설치된 앱의 오프라인 실행은 미검증이다. 현재 원본 PNG에서 얻은 12개 파생 에셋은 약 11MB라 최초 캐시에 시간이 필요하다. 정식 버전에서는 시각 비교를 거친 WebP 최적화가 적절하다.

## 다음 단계에 필요한 자료

1. 반죽: 같은 시점·중심·조명의 둥근 덩어리 → 중간 2~3상태 → 현재 평평한 도우. 밀대는 도우와 분리한 투명 PNG, 위·아래 레이어가 필요한 손잡이/그림자. 단순 확대만으로 반죽을 흉내 내지 않는다.
2. 오븐: 문이 열린/닫힌 몸체, 문 전경 레이어, 내부 불빛, 넣기 전 빈 트레이. 같은 시점의 생피자/구워진 도우·소스·녹은 치즈·익은 각 토핑. 김/불빛은 Canvas 또는 CSS로 표현 가능하다.
3. 재료 품질: 서로 겹치지 않은 페퍼로니 1장, 버섯 1조각, 치즈 가닥 4~6종의 투명 PNG. 모든 이미지에 같은 조명·시점·선명도를 적용한다. 현재 무더기에서 잘라내는 한계를 제거한다.
4. 이미지 제작은 이 조건의 개별 원화가 필요하다. ChatGPT 이미지 생성 기능으로 별도 제작한 뒤 투명도와 가장자리, 실제 착용 크기를 다시 검수하는 방법을 권장한다.
5. 이후 다른 요리는 이 시험판의 좌표계·입력/동작 기록·텍스처 마스크를 재사용하되, 단계 상태와 개별 그래픽을 요리별로 분리한다. 이번에는 기존 공통 요리 엔진을 변경하거나 전체 2.0 엔진을 미리 만들지 않았다.
