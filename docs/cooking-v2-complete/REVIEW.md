# 요리놀이 2.0 완성 버전 검수

## 기준과 범위

- 기준 main: 54f9db3 (PR #37 아이스크림 통합 병합 후).
- 작업 브랜치: release/cooking-v2-complete, Draft PR / base main.
- 기존 피자·햄버거·세 컵케이크·아이스크림을 재사용한다. 음식 원본, 합성 로직, 저장 스키마, 종합 홈, 배포 workflow는 변경하지 않는다.
- 기존 전체 게임 검사는 실행하지 않는다. 색칠·벽돌·기억력 및 구버전 요리·코디놀이는 이번 검사 대상에서 제외한다.

## 발견 사항과 최소 보완

1. 주방 선택 화면에는 피자와 준비 중 메뉴 3개가 큰 카드로, 나머지 실제 요리는 작은 링크로 표시되어 있었다. 기존 음식 PNG를 HTML 요소로 조합해 같은 크기의 실제 요리 카드 4개로 정리했다. 새 이미지 파일을 만들지 않았다.
2. 햄버거의 예전 개별 메뉴에는 완성된 컵케이크·아이스크림이 준비 중으로 남아 있었다. 해당 두 자리를 실제 게임 링크로 바꿨다. 기존 개별 메뉴와 URL은 유지했다.
3. 햄버거·컵케이크의 '요리 선택'은 각 게임의 소개 화면으로 돌아갔다. 두 게임의 헤더 및 완성 화면을 공통 주방 선택 화면으로 연결했다. 놀이터 이동은 주방 헤더를 거친다.
4. 피자·햄버거 완성 화면에서 선택 화면으로 나가기만 해도 작품 기록이 초기화됐다. 단순 나가기에는 기록을 보존하고, 기존 새 제작 시작 또는 확인창을 통한 초기화는 유지했다.
5. 기존 장식·굽기·PNG·진행 단계는 재작성하지 않았다.

아이스크림 완성의 '아이스크림 가게로'는 작품을 유지한 채 같은 게임 1단계로, '꾸미기 수정'은 3단계로 돌아간다. 이 차이는 의도된 기능이므로 유지했다. 피자 완성 뒤 카드의 '만들기 시작'은 기존 방식대로 새 피자를 시작하며, 다른 세 요리는 저장된 완성 화면으로도 복귀한다. 장식 종류에 맞는 되돌리기 명칭도 유지한다. 피자 소리 설정의 재실행 유지 및 게임별 축하 효과의 세부 통일은 이번 최소 보완 범위 밖이다.

- 햄버거: kids-game-playground:v1:game:cooking-v2:burger:prototype:r1

키·스키마를 변경하지 않는다. 네 게임에 각각 유효한 진행 기록을 넣은 뒤 각 요리의 재실행, 초기화 취소·확정 및 나머지 세 기록의 바이트 보존을 검사한다. 세 컵케이크의 예전 한 컵 기록 가져오기는 기존 명시적 동의 흐름을 유지한다.

## 검사 범위와 증거

전용 설정 tests/cooking-complete.config.ts에서 기존 핵심 검사 12개와 통합 검사 8개, 총 20개만 선택한다.

- 실제 터치·드래그로 피자·햄버거·세 컵케이크 제작 및 PNG 다운로드
- 피자·햄버거 초기화/되돌리기, 컵케이크 이전 기록 보존·가져오기
- 아이스크림 용기·스쿱·맛 10종, 토핑 드래그, 최대량·수정·저장·완성, 컵/콘 1~3스쿱 PNG
- 메뉴 4카드 동일 크기와 실제 진입·돌아오기: 1280×800, 390×844, 844×390
- 네 요리별 저장·복원, 초기화 취소·확정, 다른 요리 기록 보호, 소리 조작
- 기존 캐시 파일 존재 및 새 브라우저 오프라인에서 네 게임 진입·주방 왕복
- 타입·운영 빌드와 GitHub Pages 경로 확인

실행 결과는 PR 본문 및 해당 커밋의 Checks를 확인한다. 대량 캡처는 Git에 추가하지 않고 Actions의 cooking-complete-review 자료에 보관한다. 메뉴/각 게임의 세 화면 크기 캡처, 실제 완성 화면과 PNG, 저장 보호·오프라인 증거를 포함한다.

## 남은 한계와 다음 종합 홈 연결

- 실제 삼성 갤럭시탭·갤럭시폰에서 검증하지 않았다. 브라우저의 화면 크기와 터치 입력으로 검사했다.
- 게임별 완성 화면, PNG의 접시·배경 포함 정책, 피자의 페이지 한정 소리 설정은 다르다. 조작을 방해하지 않는 차이는 그대로 두었다.
- 세로로 긴 3스쿱은 작은 가로폰에서 작게 보인다. 기존 음식 배치와 토핑 앞쪽 레이어를 이번에 바꾸지 않았다.
- 큰 기존 번들/이미지의 최초 다운로드와 오프라인 준비 시간이 필요하다. 실기에서 캐시 준비 후 비행기 모드 확인을 권장한다.
- 다음 종합 홈 작업은 공통 주방 주소 한 곳을 입구로 사용한다. 이미 존재하는 구버전 요리·코디 메뉴를 이번 작업에서 지우거나 새 입구와 뒤섞지 않는다.
- 피자 #pizza, 햄버거·컵케이크 #play, 컵케이크의 이전 기록 경로와 네 저장 키를 유지한다. 일괄 localStorage.clear를 사용하지 않는다.
- 기존 BASE_URL과 service worker 범위를 유지한다. 메뉴 썸네일도 기존 Vite 출력물 캐시 목록에 자동 포함된다. 별도 배포 설정 수정이 필요 없다.
- main 병합·GitHub Pages 배포는 실행하지 않는다. 검토 후 사용자가 별도로 승인한다.

로컬 결과: 선택한 핵심 20개 항목 확인. 처음 실행의 검사 자료·버튼 이름 오류 2개를 수정한 뒤, 최종 메뉴·저장 보호·오프라인 및 컵케이크 돌아가기 9개를 재실행하여 모두 통과했다. 기존 전체 게임 검사는 실행하지 않았다. 타입·운영 빌드·Pages 경로 검사도 통과했다. GitHub 최종 커밋의 검사 결과는 PR에서 확인한다.
