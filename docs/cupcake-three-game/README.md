# 달콤한 컵케이크 — 세 개 동시 제작

## 기능과 실행 경로

기존 `prototypes/cooking-v2/cupcake/` 경로에서 세 컵 제작을 시작합니다. 통합 홈과 다른 요리 경로는 바꾸지 않았습니다. 새 게임은 반죽 만들기 → 세 컵 채우기 → 함께 굽기 → 각각 꾸미기 → 함께 완성으로 연결됩니다. 시간 제한과 실패 판정은 없습니다.

- 재료 그림 네 장을 누르거나 볼로 드래그합니다. 카드 전체 대신 #29에서 검수한 음식 질감 부분만 약 750ms 동안 투입합니다. 빈 볼에서 네 재료가 보이고, 원형 거품기 조작에 따라 기존 매끈한 반죽 볼로 이어집니다.
- 세 컵은 각각 25%씩 반복 터치하거나 컵 위를 문질러 채웁니다. 세 컵 모두 100%일 때만 오븐으로 갑니다. 별도의 컵 트레이 도구를 선택하지 않습니다.
- 문 열기 → 트레이 드래그 → 문 닫기 → 약 3초 굽기 → 문 다시 열기 순서입니다. 드래그가 어려울 때 쓸 수 있는 '트레이 넣기' 버튼도 제공합니다. 숨김 화면·요리 선택·초기화 확인창에서는 진행을 멈춥니다.
- `cup-1`, `cup-2`, `cup-3`의 크림 종류·짜기 진도·장식 ID/종류/좌표/크기/회전·완료 상태·되돌리기 이력을 독립적으로 유지합니다. 세 선택 카드는 실제 디자인 미리보기입니다. 맛 선택만으로 완료되지 않고 크림을 실제 짜야 합니다. 장식 후 각 컵 완료를 눌러 세 개를 완성합니다.
- 바닐라/딸기 크림, 세 종류 스프링클, 장식 빼기와 선택한 컵만 되돌리기는 기존 모델과 렌더러를 재사용합니다.
- 세 디자인과 기존 접시를 동일한 공통 합성 함수로 화면/1400×1400 투명 PNG에 출력합니다. 배경·문구·버튼은 PNG에 들어가지 않습니다.

## 기존 코드와 원화의 재사용

신규 그림 생성·원본 PNG 덮어쓰기 없이 승인된 8종(카드4, 빈 트레이, 컵 앞/뒤, 빈 볼)을 사용합니다. 기존 컵케이크 원본, 반죽 볼, 표면 질감, 크림2, 장식3, 주방·접시·거품기·짤주머니도 재사용합니다. 보류됐던 후보 8장은 로딩하지 않습니다.

`three/graphics.ts`는 #30의 `composition.json` 좌표를 직접 읽습니다. 1254²에서 뒤/안쪽 → 내용물 → 공통 앞면을 합성한 뒤 전체를 동일 배율로 줄입니다. 앞면 RGBA를 최종 확정하여 반투명 테두리의 중복 합성을 방지합니다. 굽기 진도에 따라 기존 케이크 내용물만 170px 아래 위치에서 원래 위치로 이동하고, 생반죽과 교차 전환합니다. 컵 전체를 확대하거나 늘이지 않습니다. 트레이의 세 앵커 `(393,680)/(902,680)/(1404,680)`, 배율 `.45`, 앞쪽 보호선 y=690을 유지합니다.

볼 전환은 #30 제작 도구의 원본 음식 검출·48px 내부 연결 마스크(327,036픽셀)를 재사용합니다. 내용물 영역만 색을 보간하고 나머지 1,245,480픽셀은 그대로 둡니다. 단순히 두 볼 이미지를 반투명으로 겹쳐 외곽 알파가 바뀌지 않게 했습니다. y=650이라는 수평선 아래에는 원본 반죽 일부도 있어 전환 검사에서 그 전체를 앞면으로 간주하지 않습니다. 원본 기준 내부 마스크 밖과 실제 아래 앞면(y≥720)을 보호 영역으로 검사합니다.

`Scenes.tsx`의 기존 오븐에 선택적 트레이 내용물과 구운 뒤 문 열기 표시만 추가했습니다. 기본 인자를 사용하는 기존 한 컵 렌더링은 그대로입니다. `legacy.tsx`는 이전 진입 파일을 보존한 것으로 `#legacy-play`에서 이전 기록을 확인할 수 있습니다. 기존 한 컵 회귀 테스트는 이 명시적 보존 경로로 실행합니다. 기본 경로에 대해서는 새 세 컵 테스트를 별도로 실행합니다.

추가 PNG는 Vite 이미지 URL로 묶여 기존 오프라인 캐시에 포함됩니다. 오프라인 지원 등록은 공통 진입점에서 페이지 load 이전에 준비합니다. 화면을 나중에 불러오는 구조에서 load 이벤트를 놓치는 문제를 방지했습니다.

검증 과정에서 Vite가 제거한 CSS 전용 빈 파일이 캐시 목록에 남는 빌드 문제도 확인했습니다. `vite.config.ts`의 캐시 생성 순서만 `post`로 바꾸어 정리 완료 후 실제 파일 목록을 사용합니다. Pages 주소·빌드 진입 경로·배포 작업·캐시 정책·기존 저장 키는 바꾸지 않습니다. 최종 캐시 파일의 존재 여부를 검사하는 자동 테스트를 추가했습니다. 로컬 미리보기 서버의 HTML 대체 응답이 없는 파일 오류를 숨길 수 있어, 브라우저 오프라인 검사와 실제 파일 검사를 함께 실행합니다.

## 저장과 이전 기록

- 새 키: `kids-game-playground:v1:game:cooking-v2:cupcake:three:r2`, version 2.
- 이전 r1 키는 삭제·수정하지 않습니다. 기존 피자·햄버거·다섯 게임 키도 건드리지 않습니다.
- 첫 실행 시 이전 기록이 있으면 새 버전을 자동 저장하기 전에 선택창을 엽니다. 새로고침해도 동의 전에는 창을 유지합니다.
- '기록 보관 후 새로 만들기'는 원문을 새 키의 `:legacy-archive`에도 복사하고 새 세 컵을 시작합니다. 원래 r1도 그대로 남습니다.
- 검증 가능한 꾸미기/완성 기록만 1번 컵에 가져올 수 있습니다. 2·3번은 구운 기본 컵으로 시작한다는 설명과 함께 명시적으로 선택합니다. 조리 중 기록을 임의로 완성 상태로 바꾸지 않습니다.
- 현재 세 컵 초기화는 확인창을 거칩니다. 선택창 취소나 초기화 취소는 기존 진행을 유지합니다.
- 잘못된 새 저장값은 안전한 새 게임으로 읽되 다른 게임 데이터에는 접근하지 않습니다.

### 시각 검수 범위와 한계

태블릿 화면에서 음식 크기, 컵 앞면·입구 경계, 볼 테두리, 오븐 안 트레이, 서로 다른 세 장식과 접시를 직접 확인합니다. 스마트폰은 중앙의 선택한 컵을 크게 표시하고 재료는 가로 스크롤합니다. 버튼 최소 높이는 48px입니다.

재료 투입은 카드에서 얻은 작은 질감 효과이며 달걀 깨기/우유 붓기의 독립 원화 애니메이션은 아닙니다. 굽기는 기존 내용물의 이동·교차 전환이며 새로 그린 실제 물리적 반죽 변형은 아닙니다. 원본에 가려졌던 컵·볼 내부는 #30에서 승인한 추정 복원입니다. 저사양 기기에서의 프레임 성능과 실제 삼성 기기 터치는 별도 실기 확인이 필요합니다.
