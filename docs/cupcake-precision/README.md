## 실제 제작 방법

### 1. 내부 복원 후보

이미지 편집 기능으로 **기존 원본을 편집 대상으로 직접 제공**했습니다. 볼은 반죽만 제거하고 숨겨진 안쪽 벽/바닥을 복원, 컵은 기존 케이크를 제거하고 같은 종이컵의 뒤쪽/안쪽을 복원하도록 요청했습니다. 정확한 요청 문장은 `EDIT-PROMPTS.md`에 기록했습니다. CLI/API 키 방식은 사용하지 않았습니다.

복원 후보는 겉모습이 가까워도 원본 앞면의 많은 픽셀이 미세하게 달라졌습니다. 예를 들어 컵 앞면 비교 영역의 채널당 평균 차이가 약 2.166, 볼 아래 외형 비교 영역은 약 3.782였습니다. 따라서 **생성 편집 결과 전체를 최종 파일로 사용하지 않았습니다**. 후보의 필요한 내부만 취하고 앞면과 외형은 다시 원본에서 복사했습니다.

중간 복원본 2장은 `restoration-source/`에 별도 보존합니다. 이 파일들은 최종 게임용 에셋이 아니며 원본 대체용으로 사용하면 안 됩니다.

### 2. 종이컵 앞면

원본에서 아래쪽 분홍 영역과 연결된 분홍/흰 픽셀을 추적하여 흰 물결 테두리까지 포함하는 앞면 경계를 얻었습니다. 이전의 열별 평활 경계를 그대로 쓰지 않고, 원본의 실제 색 경계를 이용해 입구 곡선을 따라갑니다. 하트와 하이라이트는 색 기준으로 지우지 않고 같은 열의 앞면 영역에 포함해 원본 픽셀로 유지했습니다.

원본 전체 1254² 좌표, 발밑 기준 `(623,1082)`, 앞면 x 범위 `138~1109`를 유지합니다. 컵 전체를 늘리거나 상태별 크기를 바꾸지 않았습니다. 공유 앞면 마스크의 전체 픽셀은 323,197개이며, 알파>250인 **310,738픽셀**을 비교했을 때 빈 컵·반죽·부풂·완성에서 RGBA 변화 **0**입니다.

최종 저장된 PNG를 파일에서 다시 읽어 **실제 앞면 파일**과 **뒤→앞 일반 Canvas 합성 결과**도 검사했습니다. 앞면 310,738픽셀에서 원본 대비 변화 **0**을 확인했습니다. 결과는 `audit.json`의 `publishedFileReload`에 있습니다.

### 3. 뒤쪽/안쪽과 내용물 합성

복원된 컵에서 앞면 위로 보이는 뒤쪽/안쪽만 분리하고 공통 앞면의 물결 경계와 연결했습니다. 흰 테두리, 종이컵 하트·주름은 원본 앞면으로 유지합니다. 비어 있는 컵이 먼저 자연스럽게 합쳐지는지 밝은 체크 배경과 어두운 배경, 원본 크기 확대에서 확인했습니다. 이전의 반복된 톱니 모양 이음새와 빈 컵 뒤쪽 부재는 이 비교에서 해소됐습니다.

반죽은 기존 `batter-surface.png`를 내부 타원에 넣고, 부푸는 시험 상태는 원본 케이크 내용물만 아래로 이동시켜 덜 올라온 모습으로 합성합니다. **케이크 내용물을 늘이거나 종이컵을 확대하지 않습니다**. 내용물이 종이컵 옆으로 새지 않도록 앞면 입구 경계 위로 클리핑합니다. 완성 상태는 기존 원본 그대로입니다.

순서: `뒤·안쪽 → 입구 위로 제한한 내용물 → 공통 앞면`. 픽셀 보존용 1254² 합성에서는 공유 앞면 RGBA를 마지막에 원본 픽셀로 확정합니다. 화면 확대·축소는 이 합성 전체에 같은 배율을 한 번만 적용해야 합니다. 반투명 픽셀을 내용물 위에 단순 중복 합성하면 알파값이 달라질 수 있으므로 원본 RGBA까지 정확하게 유지하려면 이 확정 처리를 재사용하세요.

### 4. 빈 믹싱볼

원본의 노란 반죽 경계를 검출하고 같은 열 안의 흰 하이라이트까지 내부 복원 영역에 포함했습니다. 단순 노란색 제거만 하면 남는 흰 반죽 흔적을 확인해 수정했습니다. 복원본과 원본 내벽 사이의 색 경계는 **내부에 한정한 48px 연결 영역**으로 부드럽게 이어 주었습니다. 테두리·하트·받침은 원본 픽셀을 사용합니다.

복원/연결 영역 327,036픽셀을 제외한 **1,245,480픽셀(투명 배경 포함)의 RGBA 변화 0**입니다. 전체 1,572,516픽셀의 **알파 변화도 0**이라, 원본과 빈 볼을 같은 위치에서 전환할 때 기존 바깥 윤곽·바닥 위치가 달라지지 않습니다. 안쪽 벽 색상 일부는 복원 연결을 위해 바뀌며, 숨겨져 있던 바닥을 원본에서 복사했다고 주장하지 않습니다.

## 한계와 정식 개발에 넘길 조건

- 원본 케이크/반죽에 가려져 있던 컵·볼 내부는 **원본 기반 추정 복원**입니다. 실제 보이지 않던 원래 그림과 픽셀까지 같다고 검증할 수 없습니다. 보이는 외형과 장식은 원본 보존 수치로 구분해 검증했습니다.
- 세 에셋의 정렬·합성 품질 검수는 통과했습니다. 현재 추가 수작업을 필수로 요청할 실패 항목은 없습니다. 다만 실제 기기나 움직이는 화면에서 경계가 보이면 해당 부분만 보완해야 합니다.
- 이 에셋으로 정식 3개 동시 제작 개발을 시작할 수 있습니다. 게임 로직·진행 저장·터치 조작·3초간의 연속 굽기 연출은 이번 산출물이 아닙니다. 특히 부푸는 상태는 정렬 확인용 시험 합성이며 최종 애니메이션 품질 검증은 별도 작업입니다.
- 실제 삼성 기기 플레이는 이번에 검증하지 않았습니다. 자산 검사와 픽셀 검사는 데스크톱 Chromium Canvas에서 수행했습니다.
- 기존 PR #29의 실패 시험 화면은 과거 기록으로 그대로 두었습니다. 그 화면의 실패 상태를 자동으로 바꾸거나 운영 홈에 연결하지 않았습니다.

## 재현

저장소 루트에서 기존 Node/Playwright/Chrome을 사용합니다. 이미지 생성 서비스는 아래 스크립트가 다시 호출하지 않습니다. 보관된 복원 후보를 이용해 원본 픽셀 합성/검사를 재현합니다.

```powershell
node scripts/prepare-cupcake-precision.mjs
```

기본 실행은 로컬 후보와 문서만 생성합니다. 검수 통과 결과를 최종 3파일로 다시 저장하려면 `--publish`를 추가합니다. 이 옵션도 GitHub 병합이나 Pages 배포를 하지 않습니다.
