# 사계절 코디놀이 · 1차 봄 버전

이 문서는 최초 구현 기록입니다. 이후 수정된 바디·슬롯·측면 강아지와 최신 캡처는 [착용 품질 개선 안내](../dressup-fitting/README.md)를 참고하세요.

이번 단계는 **캐릭터 3명 + 봄 배경 + 대표 의상 + 실제 착용 기능**입니다. 여름·가을·겨울과 계절별 10~15개 의상 확장은 다음 단계입니다. 이 대표 디자인과 착용 화면을 검토한 뒤 확장합니다. 자동 병합·자동 배포는 하지 않습니다.

## 화면과 조작

홈의 코디놀이 → 계절 선택 → 봄 옷장으로 들어갑니다. 태블릿 가로는 왼쪽 약 70%에 하루(남자아이), 보미(여자아이), 두부(강아지), 오른쪽 약 30%에 옷장을 배치합니다. 캐릭터를 선택하면 맞는 아이템만 표시합니다. 현재 선택한 친구는 발밑 점선과 이름으로 표시하고, 드래그 중 착용 가능한 친구는 발밑 테두리로 강조합니다.

그림을 끌어서 친구 위에 놓거나 아이템을 눌러 선택한 친구에게 입힐 수 있습니다. 큰 그림 부분은 드래그 영역이고, 이름 부분이나 옷장 빈 공간은 위아래로 스크롤할 수 있습니다. 기본 HTML 드래그 대신 Pointer Events와 포인터 캡처를 사용합니다. 드래그 중 옷장 그림은 유지하고 별도의 그림이 손가락을 따라갑니다. 맞지 않는 친구나 코디 공간 밖에 놓으면 코디를 변경하지 않고 짧게 안내합니다.

모자·안경 / 상의·세트 / 하의 / 신발 네 탭을 제공합니다. 지금 입은 옷의 ×를 누르면 해당 아이템만 벗깁니다. 캐릭터별 초기화와 전체 초기화는 확인 창을 거치며, 되돌리기로 초기화도 취소할 수 있습니다. 랜덤 코디는 선택한 친구만 바꿉니다. 계절 선택으로 돌아갈 때 입힌 옷을 유지하므로 진행 내용은 사라지지 않습니다. 다른 계절 카드는 준비 중입니다.

스마트폰 세로에서는 코디 공간 아래에 옷장을 놓고, 옷장 내부를 스크롤합니다. 320픽셀 폭에서도 조작 버튼은 최소 48×48 CSS 픽셀입니다. 큰 드래그가 어려우면 아이템 터치로도 입힐 수 있습니다. 키보드는 탭의 좌우 방향키/Home/End, 아이템의 Enter와 캐릭터 선택 버튼을 사용합니다.

## 직접 제작한 그림과 수량

동일한 선 색·굵기, 낮은 채도의 파스텔 색, 곡선·명암·바느질/꽃무늬를 사용한 프로젝트 자체 SVG입니다. 사람과 강아지는 서로 다른 몸통·다리·얼굴과 착용 그림을 사용합니다. 이모지나 화면 전체를 덮는 시안 이미지가 아닙니다. 외부 이미지·폰트나 유료 에셋을 요청하지 않습니다.

| 캐릭터 | 모자·안경 | 상의·세트 | 하의 | 신발 | 사용 가능한 선택지 |
|---|---:|---:|---:|---:|---:|
| 하루 | 7 | 5 | 3 | 3 | 18 |
| 보미 | 7 | 7 | 5 | 3 | 22 |
| 두부 | 4 | 4 | 3 | 3 | 14 |

**서로 다른 아이템 ID는 36개**입니다. 사람용 공용 아이템이 있으므로 위 표를 더한 54는 캐릭터별 착용 선택지 수입니다. 색만 바꾼 54개의 별도 의상을 제작했다고 계산하지 않습니다.

- 사람: 야구모자·벙거지·밀짚모자·베레모·선글라스·꽃 헤어밴드·리본, 줄무늬 티·셔츠·카디건·후드티·청재킷, 꽃 원피스·투피스, 청바지·면바지·반바지·치마·주름치마, 운동화·장화·샌들.
- 강아지: 전용 야구모자·베레모·선글라스·리본, 티셔츠·조끼·니트·하네스, 반바지·올인원·허리 리본, 네 발 운동화·장화·양말.

## 착용 정렬과 겹침

캐릭터 하나는 320×520 기준 좌표계를 사용합니다. 의상 데이터에 캐릭터 호환성, 카테고리, 슬롯, 그림 종류, 색상, 캐릭터별 앵커, 배율, 표시 순서와 충돌 슬롯을 보관합니다. 옷장과 착용 모습은 **같은 `ItemLayer` 그림**을 사용합니다. 따라서 다른 파일의 옷을 눈대중으로 확대해 붙이지 않습니다.

- 사람: 모자 (160,90), 안경 (160,135), 상의/원피스 (160,221), 하의 (160,330), 신발 (160,464).
- 강아지: 모자 (160,201), 안경 (160,256), 상의/올인원 (160,343), 하의 (160,400), 네 발 신발 (160,464). 네 신발은 각각 별도 발 위치에 그립니다.
- 몸과 의상 모두 같은 SVG 안에서 함께 확대·축소합니다. 옷은 몸통 위, 손과 얼굴은 옷 앞, 안경과 모자는 머리 앞에 그립니다.
- 모자와 안경은 독립 슬롯입니다. 원피스·투피스·강아지 올인원은 `full` 슬롯으로 상의·하의를 해제합니다. 일반 상의나 하의를 선택하면 `full`을 해제합니다. 강아지에게 사람 옷을 입히는 입력은 화면과 진행 규칙 양쪽에서 차단합니다.

## 저장·기념사진

자동 저장 키는 `kids-game-playground:v1:game:dressup:spring:r1`입니다. 세 친구의 코디, 선택한 친구, 기념사진 상태와 최근 30회의 되돌리기 기록을 저장합니다. 저장값을 검증하며 잘못된 값은 새 봄 코디로 시작합니다. 저장소가 차단되어도 플레이할 수 있고 저장 불가 안내를 표시합니다. 기존 색칠놀이·요리놀이 저장 키는 변경하지 않습니다.

한 친구에게만 옷을 입혀도, 또는 기본 옷 상태에서도 완성할 수 있습니다. 완성하면 같은 봄 배경에 세 친구가 함께 등장합니다. PNG 저장은 버튼·이름표·선택 테두리·알림·축하 효과를 제외한 SVG만 2160×1340 이미지로 변환합니다. 사진에서 다시 꾸미기로 돌아와도 코디를 유지합니다. 홈 복귀는 앱 공통 홈 버튼을 사용합니다. 소리 버튼은 기존 공통 설정을 따르며 착용/완성 때만 짧은 음을 냅니다.

## 추가·변경 파일

- `src/games/dressup/data.ts`: 캐릭터·계절·카테고리·대표 36개 아이템과 앵커.
- `src/games/dressup/Artwork.tsx`: 캐릭터·옷·봄 공원·착용 장면.
- `src/games/dressup/model.ts`: 착용 호환성·충돌·되돌리기·초기화·랜덤·저장 검증.
- `src/games/dressup/index.tsx`: 계절 선택·옷장·Pointer Events·기념사진·저장·확인 창.
- `src/games/dressup/export.ts`: UI 없는 PNG 저장.
- `src/games/dressup/dressup.css`: 독립 스타일·반응형·가벼운 효과·동작 줄이기 설정 대응.
- `src/games/registry.ts`, `src/main.tsx`: 홈의 코디놀이 활성화와 안내 문구.
- `tests/dressup.spec.ts`: 코디 기능/터치/정렬/PNG/저장/오프라인 검사.
- `tests/home.spec.ts`: 준비 중 카드 수 변경 반영.
- `README.md`, 이 문서와 캡처: 사용 방법과 검토 자료.

기존 `cooking/`·`coloring/` 코드는 변경하지 않습니다. 기존 `kids-color-by-number` 저장소와 동기화 참조 자료도 수정하지 않습니다. 배포 경로는 `/kids-game-playground/`를 유지하며 새 모듈은 기존 서비스 워커에 포함됩니다.

## 다음 단계와 미검증 항목

대표 디자인과 착용 정확도를 먼저 검토합니다. 그 뒤 여름·가을·겨울을 순서대로 추가하고 계절별 추천/선택지를 늘립니다. 새 의상은 아이템 데이터와 같은 좌표계의 그림을 추가합니다. 새로운 몸 형태가 필요하면 캐릭터별 앵커와 그림도 함께 검증해야 합니다. 다른 계절 활성화 시에는 저장 형식과 배경을 추가해야 하며 준비 중 카드만 열어서는 안 됩니다.

이번 버전은 카테고리별 10~15개 목표와 여름·가을·겨울 배경/의상을 아직 구현하지 않았습니다. 실제 갤럭시탭·갤럭시 스마트폰에서의 손가락 조작, Android 다운로드/갤러리 표시와 실제 스피커 출력은 **미검증**입니다. 브라우저 크기/터치 입력·PNG 파일 다운로드 검증을 실제 기기 성공으로 대신 보고하지 않습니다.

## 실행한 검증 결과

TypeScript 검사, 프로덕션 빌드, GitHub Pages 파일 경로 검사 통과. 전체 Playwright 브라우저 검사 **82개 통과**(기존 67개 + 코디놀이 15개). 54개 캐릭터별 착용 선택지를 모두 입혀 좌표 범위와 의상 슬롯을 검사하고 위 착용 비교표를 생성·육안 검토했습니다. 1280×800 / 1280×720 / 360×800 / 320×640 / 800×360 화면을 검사했습니다. 기존 색칠놀이의 큰 데이터 청크에 대한 빌드 안내는 남아 있으며 빌드는 성공합니다.
